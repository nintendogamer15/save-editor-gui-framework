# SaveEditor.Generated

A themed, testable save-editor shell generated by `dotnet new save-editor`,
built on the [Save Editor GUI Framework](https://github.com/nintendogamer15/save-editor-gui-framework)
(`SaveEditor.Ui`).

Everything below already works: run `src/SaveEditor.Generated`, click
**Open sample save**, edit a field, press **Apply**, and save. The rest of
this file is about turning it into *your* editor.

## Running it

```text
dotnet run --project src/SaveEditor.Generated
```

```text
dotnet test tests/SaveEditor.Generated.Tests
```

## Replacing the demo format

The demo format is invented for this template and is not modelled on any
real game. Three files are it, and every one of them is marked
`REPLACE ME FIRST` at the top:

| File | What it does | What yours should do |
| --- | --- | --- |
| `src/SaveEditor.Generated/Document/DemoSaveDocument.cs` | The in-memory shape of a fake save | Model your game's actual save data |
| `src/SaveEditor.Generated/Document/DemoSaveDocumentComparer.cs` | Value-compares two documents field by field | Compare your own document type the same way, unless it's a record |
| `src/SaveEditor.Generated/Codecs/DemoSaveCodec.cs` | Reads/writes an 8-byte-magic-plus-JSON toy format | Decode/encode your real format's bytes |
| `src/SaveEditor.Generated/Codecs/DemoSaveDetector.cs` | Recognizes the demo format's magic prefix | Recognize your format from its own header |

`DemoSaveDocumentComparer` exists because `DemoSaveDocument` is a mutable
class with no equality contract. `SafeFileWorkflow`'s pre-replace round-trip
check — decode the freshly serialized bytes and compare against the document
in memory — defaults to `EqualityComparer<T>.Default`, which compares a
class like this one by reference and would fail that check on **every**
save, not just a broken one. If your document type is a record, its
compiler-generated value equality already does the right thing and you can
delete this file; if it's a mutable class, keep the pattern.

`src/SaveEditor.Generated/Sections/DemoSectionFactory.cs` builds the one
example section over a `DemoSaveDocument`. Replace it with sections over your
own document type; it demonstrates every field kind the framework ships —
text, numeric (with a spinner), boolean, choice, a caution shown alongside an
editable value (`WarningText`), and read-only — so it doubles as a reference
while you build your own.

`Document/DemoSampleFile.cs` and the **Open sample save** button in
`MainWindow.axaml`/`.axaml.cs` exist only because the demo format has no
save files sitting on anyone's disk already. A real editor points users at
wherever their game actually keeps its saves; delete both once your codec is
in.

Nothing else needs to change to swap formats: `MainWindow.axaml.cs` composes
`SaveCodecRegistry`, `SafeFileWorkflow`, and `DocumentSession` generically
over whatever document type and codec(s) you register.

## What the framework guarantees, and what it does not

**Save As is the default write path, and `Ctrl+S` always means Save As.**
Overwriting an existing file is a separately named action
(`Overwrite + Backup`) that always writes and hash-verifies a backup first.
On any failure, the bytes at the target path are exactly the pre-operation
bytes — not guaranteed and not claimed: file identity, hard-link aliasing,
views other processes hold through open handles, and timestamps.
Permissions are preserved. See the framework's `README.md`, "Safety and file
workflow", and `PLAN.md` §7 for the full contract.

**A codec is a correctness boundary, not a security boundary.** `ISaveCodec`
implementations — including yours — run in-process, at full privilege, as
part of this application. The framework cannot sandbox a codec, and you
cannot sandbox one you install from someone else. What it *does* provide is
containment of honest mistakes: bounded inputs, isolated and time-boxed
format detection, serialization into bounded memory rather than onto the
destination file directly, exception containment at the workflow boundary,
and verification — not trust — of a codec's claim that it preserves data it
does not understand. Install only codecs you trust, review any you didn't
write yourself, and never point this application's codec pipeline at a file
whose source you don't trust just because the format looks familiar. See the
framework's `README.md`, "What this does not defend against", and
`PLAN.md` §8 for the full threat model.

**Typing never touches your document.** A draft lives on the field until
Apply, which is what lets it survive navigating to another section and back.
The exit guard is driven by `HasPendingEdits` — that's why
`DocumentSession<T>.PendingEditProbe` is wired to the hero section in
`MainWindow.axaml.cs`; an editor that adds more sections must fold every
section's pending state into that same probe, or edits in the new section
can be discarded without asking.

**Settings are fail-soft; saves are fail-loud, deliberately.** A theme
preference that fails to persist just doesn't persist. A save that
fails is always reported, and never partially applied.

## Where things live

- `src/SaveEditor.Generated/MainWindow.axaml.cs` — the composition root: every
  framework piece (`EditorShellViewModel`, `DocumentSession`,
  `SafeFileWorkflow`, `SaveCodecRegistry`, `ThemeController`,
  `EditorSettingsStore`, `WindowEditorHost`, `ThemedUserInteraction`) wired
  together with plain constructors, no DI container required.
- `src/SaveEditor.Generated/App.axaml` — registers a base Avalonia theme
  (`FluentTheme`) and then `SaveEditorTheme`. Order matters: the base theme
  supplies control behaviour, the framework theme supplies the visual
  contract.
- Settings persist at `%LocalAppData%\SaveEditor.Generated\settings.json` on
  Windows (`~/.local/share/SaveEditor.Generated/settings.json` on Linux) —
  the segment tracks whatever name you gave the project with `-n`.

## Next steps

1. Delete the three `REPLACE ME FIRST` files and write your own document,
   codec, and detector.
2. Update `Sections/DemoSectionFactory.cs` (or add more section factories)
   for your document's actual fields.
3. Fold every section's `HasPendingEdits` into `PendingEditProbe` in
   `MainWindow.axaml.cs`.
4. Remove the **Open sample save** button and `DemoSampleFile.cs`.
5. Give the shell your own branding in `MainWindow.axaml`'s
   `EditorShell.Branding` slot, and set an editor-preferred accent by
   passing it to `ThemeController`'s constructor.
